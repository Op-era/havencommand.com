How do you stop an AI agent from overwriting a live script?

Lock the draft. Let the agent propose. Merge only on a red/green Approve. The live script is not a chat buffer.

Shane Foster  ·  AI Integrations Engineer, Haven Command LLC  ·  August 10, 2026

What problem did we actually hit?

Problem

ScriptForge AI is a screenwriting product, not a chat window with a .fountain export. Writers stay in a live script for hours. Agents track structure, continuity, and character. Those two facts collide the moment an agent write lands on the same document the human is typing.

The failure is obvious after it happens and invisible in a demo: you asked for a polish on scene three and the live draft you were finishing is gone. “The model was helpful” is not a comfort. I will not ship a writing tool that treats the script as a disposable buffer.

How did Haven Command solve it?

Solution

The live script locks. Agents do not write through it. They propose a rewrite. The writer sees a review and hits green to approve or red to throw it away. Until then, the draft on the page is the draft on the page.

That sounds like product taste. It is also an integration rule: there is one source of truth for the document, and the model is a petitioner. Same rule as grounding the D4Chess coach on Stockfish PVs — the model does not get to be the ledger.

Approve is not a modal for show. It is the merge. Reject leaves the lock intact. The writer stays in flow instead of reconstructing a scene from memory.

If the model can write the document, it can destroy the document. Put a lock on the live copy.

Why does this help someone hiring custom AI work?

For clients

Companies ask for “AI that edits our docs.” The production version is AI that proposes edits to a locked record, with an explicit accept. Questions this write-up answers

What was the ScriptForge overwrite problem?

An agent rewrite could land on the live script a writer was still editing. The draft disappeared into the model’s last pass.

What is the red/green Approve review?

The agent proposes a change. The writer accepts (green) or rejects (red). Nothing hits the locked script until that decision.

Do client tools need the same lock?

Yes, if an LLM can edit a record humans also edit — contracts, notes, CRM fields, screenplays. Dual-write without a lock is data loss with better grammar.
