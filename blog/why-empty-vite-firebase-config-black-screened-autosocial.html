Why did an empty Vite Firebase config black-screen AutoSocial on Fly?

Vite inlines env at build time. If Fly builds without the public Firebase args, the bundle boots with empty config and the UI dies. Pass the args at build.

Shane Foster  ·  Founder, Haven Command LLC  ·  July 6, 2026

What problem did we actually hit?

Problem

Locally, AutoSocial loaded. On Fly, it was a black screen. No stack trace for the user. The app “was deployed.” It just could not become itself.

Vite embeds VITE_-prefixed values when it builds. If the Fly build runs without those public Firebase config values, the bundle contains empty strings. Firebase never initializes. React has nowhere to go. This is not mysterious once you have seen it. It is very mysterious at 1 a.m. if you only exported the vars on the running machine.

How did Haven Command solve it?

Solution

The Fly build now receives the Firebase public config as build arguments so Vite can inline real values. The runtime still needs whatever the server needs; the client needs what it needed at compile time.

We treat a missing public config as a failed deploy, not a page that paints black and shrugs. Same standard as an empty coach payload: “resolved” is not the same as “usable.”

A client bundle cannot read the secrets you remembered after the build. Vite already baked the empty string.

Questions this write-up answers

Why was AutoSocial a black screen on Fly?

The Vite build ran without Firebase public config, so the shipped JavaScript initialized an empty app. The UI never reached a usable state.

Why didn’t a runtime env var on the VM fix it?

Vite replaces VITE_ variables at compile time. A process env on the running machine does not rewrite the already-built bundle.

What is the client takeaway?

Treat frontend config as a build input. Document it. Fail the deploy if required public keys are missing — do not ship a quiet black screen.
