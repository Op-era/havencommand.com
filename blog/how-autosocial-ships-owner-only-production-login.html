How do you ship production login that doesn’t depend on broken email OTP?

Owner-only auth. A login path you can operate when the mail provider flakes. Production software is allowed to have one door that always opens for the owner.

Shane Foster  ·  AI Integrations Engineer, Haven Command LLC  ·  July 13, 2026

What problem did we actually hit?

Problem

Email OTP looks clean in a diagram. In production it is a dependency on someone else’s deliverability. On AutoSocial that meant a real risk: the person who has to publish this week’s content cannot get in because a one-time code never arrived.

I will not run a live product whose only door is a message I cannot guarantee. That is not security theater in the useful direction. That is an outage with extra steps.

How did Haven Command solve it?

Solution

Production login is owner-gated and does not wait on a broken OTP hop. The owner can reach the app; everyone else still has to authenticate through the designed path. We did not “disable auth.” We stopped single-homing the operator on an inbox.

This is the same class of decision as passing real config into a Fly build: the product has to boot for the person who is on the hook. Auth is part of boot.

If the only key is an email you cannot receive, you do not own the product. The inbox does.

Why does this help someone hiring custom AI work?

For clients

AI products fail in boring places: login, billing, empty env, a provider timeout. Companies hiring integration work already know this. Founders funding a first build often find out at 11 p.m. I build owner-operable auth into the loop.

Questions this write-up answers

What went wrong with email OTP?

One-time codes are fine until deliverability dies, a provider rate-limits you, or a message lands in spam. Then nobody can sign in — including the owner.

What did AutoSocial ship instead?

An owner-gated production login that does not depend on that OTP path succeeding in the moment. The operator can still reach the product.

Is this an excuse to skip real auth?

No. Users still authenticate. The point is a production door that is not single-homed on a flaky mail hop.
